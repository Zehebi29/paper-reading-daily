# SkillOpt：自进化Agent技能的执行策略

**arXiv**: 2605.23904 | **GitHub**: https://aka.ms/SkillOpt | **机构**: Microsoft Research, 上海交通大学, 同济大学, 复旦大学

---

## 一句话总结

SkillOpt 首次将 agent skill（技能文档）当作可训练的“外部状态”，用类深度学习优化器的流程（学习率、验证集、动量）在文本空间中对 skill 进行可控编辑，在 6 个 benchmark x 7 个模型 x 3 个执行框架的 52 个测试单元上全部取得最优或并列最优，GPT-5.5 平均提升 +23.5 分。

## 问题背景

Agent 技能（skill）是指导 LLM 如何收集证据、调用工具、格式化输出的自然语言规程文档。现有方法要么手写、要么一次性生成、要么通过无约束的自修改来演化——但都不像深度学习优化器那样可复现、可验证。没有一个方法能在收到反馈后可靠地持续改进。SkillOpt 的核心理念就是：把 skill 当作 frozen agent 的外部可训练状态，用优化器来做可控的文本空间编辑。

## 核心方法

1. **Rollout 批处理** —— Frozen 目标模型用当前 skill 执行任务，产生带分数的轨迹数据。
2. **Minibatch 反思** —— 优化器模型（如 GPT-5.5）分别分析失败和成功案例，提出结构化的 add/delete/replace 编辑。
3. **有界文本更新** —— 引入文本学习率（textual learning rate）限制每步最大编辑数，防止有用规则被擦除。
4. **验证门控** —— 候选 skill 只在 held-out 集上严格提升分数时才被接受，防止性能漂移。
5. **拒绝编辑缓冲区** —— 被拒的编辑被存储为负反馈，供后续优化器参考避免重复错误。
6. **Epoch 级慢更新/元更新** —— 比较相邻 epoch 的 skill 版本，写入受保护的长期指导规则；优化器侧维护一个元 skill 记录有效编辑模式。

部署时只需一个 best_skill.md（约 300-2000 token），零推理开销。

## 关键结果

| 设置 | 无 Skill | SkillOpt | 提升 |
|------|---------|----------|------|
| GPT-5.5 Direct Chat (6 benchmark 平均) | 58.8 | **82.3** | **+23.5** |
| GPT-5.5 Codex | — | — | **+24.8** |
| GPT-5.5 Claude Code | — | — | **+19.1** |
| 最优单 cell 基线平均 | 76.9 | — | SkillOpt **+5.4** |
| 全部 52 个测试单元 | — | **最佳或并列最佳** | 100% |

代表性 benchmark 提升（GPT-5.5 Direct Chat）:

| Benchmark | 无 Skill -> SkillOpt | 提升幅度 |
|-----------|-------------------|---------|
| SpreadsheetBench | 41.8 -> **80.7** | **+38.9** |
| OfficeQA | 33.1 -> **72.1** | **+39.0** |
| LiveMathematicianBench | 37.6 -> **66.9** | **+29.3** |
| DocVQA | 78.8 -> **91.2** | +12.4 |
| SearchQA | 77.7 -> **87.3** | +9.6 |
| ALFWorld | 83.6 -> **95.5** | +11.9 |

消融实验关键发现：Epoch 级慢更新+元更新是最关键的组件——移除后 SpreadsheetBench 从 77.5 跌至 55.0（-22.5）。文本学习率和拒绝编辑缓冲区也各自贡献 2-5 分。

跨模型、跨框架、跨 benchmark 的迁移实验中，所有迁移均为正迁移。最惊人的是 Codex 训练的 SpreadsheetBench skill 迁移到 Claude Code，获得了 +59.7 分的增益。

## 亮点

- 将深度学习优化器的概念系统性地映射到文本空间编辑，类比清晰且实用（学习率->编辑预算，验证->门控，动量->慢更新）
- 所有 52 个测试单元全面碾压，没有任何一个反例——这在 agent 论文中极为罕见
- 迁移实验覆盖跨模型规模、跨执行框架、跨 benchmark，且全部正迁移，说明 skill 确实捕获了可复用的规程知识
- 部署零额外开销，输出的 skill 只有几百 token，非常轻量实用

## 局限

- 依赖强优化器：作者使用 GPT-5.5 作为优化器，训练阶段成本不低（0.6M-46.4M token 每个百分点）。虽然消融显示目标模型自优化也能恢复 56-74% 的增益，但最佳效果仍需更强模型驱动
- 需可评分任务：SkillOpt 依赖一个能产生标量分数的验证器/评估器，并非所有任务场景都有清晰的客观评分
- benchmark 多样性有限：6 个 benchmark 覆盖了 QA、表格、数学、具身任务，但未涉及代码生成、多轮对话等更开放的 agent 场景
- skill 长度限制：输出的 skill 为 300-2000 token，可能无法编码非常复杂的多层次规程

## 个人评价

SkillOpt 是我今年读到的最实用的 agent 论文之一。它的核心贡献不是某个 fancy 的新模型或新 benchmark，而是一个系统性的方法论——告诉你如何可靠地、可复现地改善 agent 的行为。

对于我自己的 GWS 焊缝路径规划研究，启发很大：我们的路径规划策略其实也是一种"skill"——编码了如何选择焊点、如何避障、如何处理特殊几何。如果能用一个离线优化器（像 SkillOpt 那样）基于仿真反馈来迭代改进规划策略，而不是靠手调规则或简单的自修改，可能会有本质性的提升。

另外，SkillOpt 的"验证门控"和"文本学习率"概念直接对标了深度学习训练中的防止过拟合手段，这种跨领域的迁移思考本身就很值得学习。如果你的工作涉及 prompt/skill 的反复调试，强烈建议读一读这篇。
