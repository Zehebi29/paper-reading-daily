# TurnSight：面向工具集成推理的回合级事后自蒸馏

**arXiv**: 2608.04007 | **GitHub**: https://github.com/quchangle1/TurnSight | **机构**: 中国人民大学高瓴人工智能学院 + 百度

---

## 一句话总结

TurnSight 提出一种回合级（turn-level）事后自蒸馏框架：直接用智能体自己轨迹中的工具执行结果构造多视野特权上下文，跨视野投票选出可靠信号，以有界符号感知权重调制 RL advantage——不改优化方向，只调大小，在 Qwen3-8B 上三个工具使用基准平均分 42.02，比此前最优方法 MatchTIR 高 7.7%。

## 问题背景

工具集成推理（TIR）让 LLM 通过多轮工具交互解决复杂任务，但轨迹级 RL（如 GRPO）把同一 advantage 分给所有轮次，无法区分哪一步工具调用真正有用——长程 TIR 的时序信用分配问题很严重。现有在线自蒸馏（OPSD）方法用 ground-truth 答案或检索技能做特权上下文，但这些外部参考与学生策略实际访问的状态不对齐，而且 token 级监督会在一轮交互内给出互相冲突的信用信号。

## 核心方法

- **执行条件事后视野**：把学生自己轨迹中后续工具调用的执行结果（lookahead depth 1/2/3）拼进冻结参考策略的上下文，算 token 级 log 概率差作为事后证据——特权信息来自学生走过的状态，而不是外部答案。
- **回合级聚合**：TIR 的自然决策单元是一整轮工具交互（推理+选工具+构造参数），把 token 级差距在回合内平均，避免格式 token 和参数变体带来的冲突信号。
- **跨视野方向一致的教师选择**：三个不同 lookahead 的教师先对回合信号方向做多数投票定共识方向，再在共识方向内选信号最强的教师，过滤掉孤立不可靠的评估。
- **组归一化 + 有界符号感知加权**：在同一个 prompt 的 16 条 sibling rollouts 内对选中的回合信号做 z-score 归一化；权重 w = 1 + εw·tanh(sign(A_base)·δ̂)，与 base advantage 同向就放大、反向就衰减，且限制在 [1-εw, 1+εw]，不改变 RL 优化方向。
- **即插即用**：无额外模仿目标、无额外采样，底层 RL 算法任意（实验里用 MatchTIR 做 backbone），推理时零额外开销。

## 关键结果

| 模型 | 方法 | FTRL Avg | BFCL Avg | ToolHop | 总平均 |
|:---|:---|:---|:---|:---|:---|
| Qwen3-4B | GRPO | 30.91 | 22.90 | 21.98 | 25.26 |
| Qwen3-4B | MatchTIR | 35.91 | 30.82 | 37.56 | 34.76 |
| Qwen3-4B | **TurnSight** | **41.00** | **33.18** | **38.29** | **37.51** |
| Qwen3-8B | GRPO | 36.92 | 26.66 | 29.21 | 30.93 |
| Qwen3-8B | MatchTIR | 42.78 | 33.78 | 40.54 | 39.03 |
| Qwen3-8B | **TurnSight** | **46.92** | **37.56** | **41.58** | **42.02** |

- 8B 模型总平均比此前最优（MatchTIR）提升 7.7%，成为 SOTA；4B 模型同样全面领先。
- 消融（8B，FTRL）：去掉回合级聚合 -3.69（43.23），去掉组归一化 -3.27（43.65），去掉多教师选择 -1.30（45.62）——回合级聚合贡献最大。
- 特权上下文只用工具结果最好（46.92），加上 ground-truth 答案反而降到 40.89——更多特权信息不等于更好监督。
- 全轨迹监督 > 只监督前 5 轮（+2.36%）> 只监督后 5 轮（+3.88%），早期工具决策影响更大。
- 超参 λ（混合系数）和 εw（调制界）都在 0.5 最优，单峰趋势。

## 亮点

- 特权上下文来自学生自己轨迹的执行结果，天然状态对齐，不依赖 ground-truth 轨迹或检索技能，保留 RL 的探索性。
- "回合"作为信用分配单元这个选择很扎实：消融证明 token 级独立监督会产生冲突信号，回合级聚合显著更稳。
- 跨视野方向一致选择的设计很巧妙——短视野看即时执行质量、长视野看延迟后果，多数投票过滤不可靠教师。
- 有开源代码（quchangle1/TurnSight），复现门槛低。

## 局限

- 只在 4B/8B 两个模型规模上验证，未见更大模型或更强 base 上的表现。
- 训练只在 FTRL 一个数据集上做，工具类型有限；训练时 3 个冻结教师分支的前向计算带来额外开销（论文未报告具体训练成本）。
- 三个 benchmark 中 out-of-domain 提升幅度明显小于 in-domain（FTRL +10 分 vs ToolHop +1~3 分），跨域泛化仍是短板。

## 个人评价

这篇和昨天读的 CoPES、前天读的 TAPO 是同一个赛道的不同解法：都在解决"稀疏轨迹奖励无法给中间步骤分信用"的问题。TAPO 用环境预测做辅助目标，TurnSight 用执行结果做 hindsight 蒸馏——但 TurnSight 的切口更细：它抓住"特权上下文必须和学生走过的状态对齐"这一点，直接否定了用 ground-truth 答案做教师的常见做法，并用实验证明加答案反而更差（40.89 < 46.92）。这个反直觉结果很有说服力，等于告诉社区：教师给的不是"答案"，而是"对当前状态的后见之明"。

对我自己研究的启发是：多轮交互类任务的监督粒度要匹配决策单元——如果决策是"一轮操作"，监督就应该按轮聚合而不是按 token。这个思路在别的 agent 场景（比如带工具调用的机器人任务）可能同样适用。另外它作为 GRPO/MatchTIR 之上的即插即用模块，工程上很友好，值得在后续实验里直接试。
