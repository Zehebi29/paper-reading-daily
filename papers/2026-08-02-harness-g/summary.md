# Harness-G：面向搜索智能体的图结构 Harness

**arXiv**: 2607.27652 | **GitHub**: https://github.com/7HHHHH/Harness-G | **机构**: 国防科技大学

---

## 一句话总结

Harness-G 把搜索智能体的自由文本查询生成改造成图结构上的有限动作选择（Select/Lookup/Answer），并配合结构化非近视信用（SNC），在 6 个 QA benchmark 上平均 F1 超过最强基线 Graph-R1 达 10.74 分（1.5B）和 3.98 分（3B）。

## 问题背景

- RL 搜索智能体（如 Search-R1）把检索建模为自由文本查询生成，用最终答案奖励优化多轮交互；现有工作主要靠过程奖励、信息增益等改善信用信号，却很少审视"检索本身在策略-环境接口上是否被正确建模"。
- 论文观察到 Search-R1 训练中的"检索等价坍缩"（retrieval-equivalence collapse）：同一问题的 rollout 继续生成不同的查询字符串，但累积的证据集越来越重叠——查询形式多样性是"虚假探索"，组内回报几乎没有有效的检索对比。
- 根源是自由文本到检索结果的 many-to-one 映射：轨迹要么证据相同回报相同（组内优势消失），要么证据相同答案不同（回报差异被下游推理污染），过程奖励也救不了，因为 rollout 组里根本没有真正不同的检索决策。

## 核心方法

- 检索接口重设计：把自由查询生成改为图引导的有限动作选择——策略从当前状态的动作菜单中选择"采纳证据句（Select）/ 沿实体查找（Lookup）/ 回答（Answer）"，环境负责构造查询、跟踪检索状态、验证并确定性执行（含去重过滤）。
- 语料图：离线程序化构建段落-句子-实体三层图（无关系、无 LLM 参与），在线暴露有限、去重、可验证、可预览的动作菜单，策略每步只做"下一步追哪个证据/实体"一个语义决策。
- SNC（Structured Non-myopic Credit）：frontier-relative credit 用冻结答案评分器 + 只读预览，比较选中动作与同状态替代动作；enablement credit 沿轨迹依赖把下游收益传播给早期使能的桥接动作。
- 即插即用：SNC 无需额外 rollout，仅增加 9-11% 每步墙钟时间；论文在 Qwen2.5-1.5B/3B 上训练，并验证了 Qwen3.5-4B、Llama-3.2-3B 及 GRPO/PPO/REINFORCE++/DAPO 的兼容性。

## 关键结果

| 模型 | 指标 | Harness-G | Graph-R1（最强基线） | 差距 |
|---|---|---|---|---|
| Qwen2.5-1.5B | 平均 F1（6 数据集） | 50.83 | 40.09 | +10.74 |
| Qwen2.5-3B | 平均 F1（6 数据集） | 55.24 | 51.26 | +3.98 |
| 3B | 2Wiki / HotpotQA / MuSiQue F1 | 65.53 / 65.87 / 46.46 | 57.56 / 56.75 / 40.51 | +7.97 / +9.12 / +5.95 |
| 3B | 平均 OOD F1（train-on-one, eval-all-six） | 47.38 | 44.10 | +3.29（30 对中赢 21） |

- 消融：动作菜单 vs 自由查询在两种信用制度下 F1 提升 >17 分（MuSiQue 上仅 outcome 奖励训练时 >35 分）；移除整个 SNC 在 2Wiki/HotpotQA/MuSiQue 分别掉 3.08 / 4.55 / 2.88 分。
- 效率：SNC 每步仅增 9-11% 墙钟时间，3B 全程约 170 GPU·h；图程序化构建 API 成本 $0（LLM 提取图需 $2.81-$4.14），每查询 5.1s。
- 交互模式：后期轮数更多（3.6 vs Search-R1 2.3 / Graph-R1 2.9），但响应 token 更短（2.5k vs 4.3k / 3.1k），总 token 成本未上升。

## 亮点

- 视角新颖：把"检索动作空间设计"作为与奖励设计正交的优化轴，识别并命名了 retrieval-equivalence collapse，用"查询形式多样性 vs 检索结果多样性"的曲线量化了虚假探索。
- 可复现性好：MIT 协议官方代码；图程序化构建（API 成本 $0）；SNC 无额外 rollout，训练开销低（3B 约 170 GPU·h）。
- 小模型收益更大：1.5B 平均 F1 提升 10.74 分且所有数据集超越基线，说明结构化动作空间对弱策略的约束红利显著。
- 鲁棒性好：多 backbone、多 RL 算法都稳定收敛，无后期崩溃；OOD 跨数据集 30 对中赢 21 对。

## 局限

- 检索被限制为"选证据/选实体"，对开放式、长尾或需要自由查询表达的场景（实时网络搜索、专有检索器）不一定适用；NQ 单跳任务上 3B 仍落后 Graph-R1 1.84 分。
- 动作菜单依赖离线建好的段落-句子-实体图，语料频繁更新的场景需要重新建图，工程成本未被充分讨论。
- 实验集中在 QA 类 benchmark（2WikiMultiHopQA/HotpotQA/MuSiQue/NQ/PopQA/TriviaQA），对编码、代理操作等更复杂的 agent 任务未验证；目前文本-only，多模态证据是作者列的下一步。

## 个人评价

这篇最打动我的不是 +10.74 分，而是它把问题定位从"奖励信号不够密"挪到了"动作空间本身有别名（aliasing）"。这和我们做 GWS 焊缝路径规划时的思路很像：与其在稀疏奖励里打转，不如先重新设计"动作"的表示，让策略面对的每个决策都语义干净、可比较。Search-R1 这类自由查询 agent 的"虚假探索"和路径规划里"轨迹长得不一样但行为等价"的问题，本质上是同一类病。

SNC 的 enablement credit 也值得琢磨：桥接动作本身不产生最终收益，却是后续成功的前提——这很像焊缝规划里的过渡段/姿态调整动作，事后看没有直接得分，却决定了整条路径的可行性。把这类"使能信用"显式建模，比 GRPO 组内优势的模糊摊派诚实得多。对我们的启发：如果能把任务改造成"有限动作 + 状态可验证 + 同状态可对比"的接口，小模型也能在复杂任务上逼近大模型效果——对算力受限的我们是个好消息。
