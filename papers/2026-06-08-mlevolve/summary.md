# MLEvolve: LLM多智能体自进化框架实现自动ML算法发现

**arXiv**: 2606.06473 | **GitHub**: https://github.com/InternScience/MLEvolve | **机构**: 上海AI实验室 (Shanghai AI Lab)

---

## 一句话总结

MLEvolve是一个基于LLM的自进化多智能体框架,通过渐进式图搜索和经验记忆实现端到端ML算法自动发现,在MLE-bench 75个Kaggle任务上以65.3%奖牌率拿下第一,仅用12小时(标准时间的一半),同时在数学算法优化任务上超越AlphaEvolve。

## 问题背景

现有LLM代理做ML工程(MLE)时遇到三个瓶颈: (1)分支间信息完全隔离,不同解题分支无法互相学习; (2)搜索过程无记忆,每次都从零开始; (3)缺乏层次化控制,策略规划和代码生成耦合在一起。这些问题导致长时间优化任务中效率低下。

## 核心方法

- **Progressive MCGS(渐进式蒙特卡洛图搜索)**: 将解题组织成有向图,通过Reference Edges实现跨分支信息流动,支持四种扩展模式(主扩展/分支内进化/跨分支参考/多分支融合)。内置滞进检测和熟图启发的渐进式探索-利用切换。
- **Retrospective Memory(回顾式记忆)**: 冷启动时有预置的领域知识库,运行中自动积累结构化记忆(规划/代码/指标/分析)。检索用BM25+FAISS+互排名融合,支持规划场景和调试场景的差异化检索。
- **Hierarchical Planning & Adaptive Code Generation(层次化规划与自适应代码生成)**: Planner和Coder解耦,支持三种代码生成模式 — Base(全新生成)/Stepwise(模块化)/Diff(增量补丁),根据搜索状态自动切换。
- **多智能体协作**: Planner智能体负责策略规划,Coder智能体负责代码实现,各智能体有独立的记忆检索策略。

## 关键结果

| 指标 | MLEvolve | 第二名 (MARS+) | 第三名 (AIBuildAI) |
|:---|:---|:---|:---|
| 平均奖牌率 | **65.3%** | ~60% | ~55% |
| 金牌率 | **34.7%** | - | - |
| 有效提交率 | **100%** | - | - |
| Above-Median率 | **76.0%** | - | - |
| 运行时间 | **12h** | 24h | 24h |

- MLE-bench 75个Kaggle任务,使用Gemini-3.1-Pro-preview
- 数学算法优化: 15个任务中11个取得最佳结果,超越AlphaEvolve和AlphaEvolve-v2
- 消融实验: 移除Progressive MCGS后奖牌率从81.82%降至68.18%,移除记忆模块降低13.64%

## 亮点

- 框架通用性强: 在ML工程和数学算法两个完全不同的领域都取得SOTA,说明框架设计的方法论有真正的泛化能力
- 效率突出: 12小时达到24小时方法的水平,实用性强
- 代码开源完整: GitHub仓库提供了完整的配置、运行和冷启动支持
- 消融实验充分: 每个核心组件都有单独的消融实验,证明了各设计的必要性

## 局限

- 依赖闭源模型(Gemini-3.1-Pro-preview)而非开源模型,复现成本较高
- MLE-bench主要是Kaggle类任务,对更广泛的ML工程场景(如分布式训练/部署)的评估不足
- 12小时的运行时间仍然较长,不适合快速迭代场景

## 个人评价

这篇论文的核心贡献在于把MCTS的图搜索思路引入到LLM代理的ML工程任务中,并通过跨分支信息流动和经验记忆解决了传统树搜索的孤立问题。这个思路对于Agent训练的启发是: 不一定要通过RL来优化Agent,搜索+记忆的组合同样可以实现自进化。另外,其框架将策略规划与代码生成解耦的设计,以及自适应的代码生成模式切换(Base/Stepwise/Diff),对于构建实用的Agent系统有直接的参考价值。不过它的局限也很明显 — 主要在Kaggle类任务上验证,能否扩展到更复杂的Agent任务(如多轮对话/工具使用)还有待观察。
