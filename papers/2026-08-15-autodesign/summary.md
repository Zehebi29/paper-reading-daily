# AutoDesign：面向长程智能体设计的元 Harness 优化

**arXiv**: 2608.13560 | **GitHub**: [Yaxin9Luo/AutoDesign](https://github.com/Yaxin9Luo/AutoDesign) | **机构**: 美团 + MBZUAI（合作：华科/北大/清华/港中文/上交）

---

## 一句话总结

AutoDesign 把论文转海报这类长程多模态设计任务建模为对 agent harness 本身的递归优化：外层循环的元优化器驱动编码智能体，基于 rollout 反馈一次只改进 harness 的一个组件，训练出的 DesignHarness 在 PosterBench 主赛道拿到 78.32 分、超过商业系统 Claude Design 7.45 分，并让 7 种模型+编码 agent 组合平均提升 12.4 分。

## 问题背景

- 多模态设计（论文→海报/幻灯片/网页）本质是一个长程 agentic 过程，系统质量取决于"模型+harness"整体；但现有系统的 harness 是静态的，反馈被当作一次性信号，无法沉淀为可复用的设计知识。
- 理想的 harness 应该对齐人类设计先验、通过经验积累可复用能力、并递归自我改进——现有范式（TextGrad/DSPy 优化组件、STOP/GPTSwarm/AFlow 搜索流程）都做不到跨任务的系统级演化。
- 论文把"如何把反馈转成持久生产能力"形式化为 meta-harness 优化问题：优化对象是系统（harness），而不是模型权重。

## 核心方法

- **双层循环架构**：内循环是 design harness（摄取源文档→生成/修订工件→规则校验+VLM 批判→定稿），外循环是 meta-harness（在任务上 rollout→评估→提出修改→接受门判定）。
- **harness 五组件分解**：上下文与记忆、工具与规格、执行运行时、编排、评估与反馈；每次外循环迭代只修改一个组件，保证单次更新的效果可归因。
- **接受门防过拟合**：候选更新仅在训练集分数提升且开发集分数不下降时被采纳，开发集结果对优化器不可见。
- **优化器即编码智能体**：承担"规划器+代码编辑器"双角色，维护跨迭代的优化记录 L（含轨迹、分数、更新计划与判定），支持回滚与对比；可选 human-in-the-loop 用自然语言引导重定向搜索。
- **PosterBench 评估协议**：100 篇论文主赛道（覆盖 AI/ML、生物医学、气候环境、经济政策、物理天文 5 个学科）+ 10 篇共享 mini 子集，7 维加权评分（忠实度/覆盖/密度/视觉证据/布局/可读性/美学），规则检查与 VLM 判断混合。

## 关键结果

| 配置（模型 / 编码 agent） | 原始分数 | +DesignHarness | 增益 |
|---|---|---|---|
| GPT-5.5 / Codex | 75.87 | 81.46 | +5.59 |
| Claude 4.8 / Claude Code | 69.55 | 74.56 | +5.01 |
| Seed 2.1 Pro / Claude Code | 54.01 | 71.83 | +17.82 |
| Kimi K2.7 / Claude Code | 57.20 | 70.12 | +12.92 |
| GLM 5.2 / Claude Code | 50.32 | 64.33 | +14.01 |
| LongCat 2.0 / Claude Code | 43.26 | 55.13 | +11.87 |
| DeepSeek V4 Pro / Claude Code | 34.73 | 54.29 | +19.56 |

- **7 配置平均**：54.99 → 67.39（+12.40 分），提升幅度 5.01–19.56 分。
- **PosterBench Main Track**：AutoDesign 78.32 最高，超 Claude Design（70.87）7.45 分、超 OpenDesign（69.45）8.87 分；Codex/GPT-5.5 配置 77.97。
- **全自主运行**：单张海报 253 次工具调用、11 次编辑回合、40 分钟完成、成本不到 3 美元。
- **人类盲评**：11 名评审、936 个响应（933 个排序判断），AutoDesign 的 Bradley-Terry 胜率 64.0%（95% CI: 55.2–77.8%），对 Claude Design 达 67.6%；基准与人类一致率随分差增大从 51.9%（0–3 分）升至 74.4%（≥20 分）。
- **演化轨迹**：初始 harness 49.00 → 自主优化到 80.88 平台 → 人类引导后 88.39；7 天演化累计 224 个子智能体、123+ 次递归迭代、54 次 harness 更新。
- **成本-性能前沿**：LongCat-2.0 每张海报仅 0.27 美元（55.13 分）→ Seed 2.1 Pro 2.75 美元（71.83 分）→ Claude 4.8 7.63 美元（74.56 分）→ GPT-5.5 10.02 美元（81.46 分）；Doubao 用 27% 成本达到 GPT-5.5 的 88% 分数。

## 亮点

- 把"harness 本身作为优化目标"做成可执行系统：模型参数冻结，改的是围绕模型的系统，方向新颖且工程可复现。
- 单组件更新约束 + 接受门（训练提升且开发不降）的组合，让每次演化都可归因、可回滚，是 agent 系统迭代开发的稳健范式。
- 跨 7 种模型/编码 agent 组合一致提升（5.0–19.6 分），说明学到的是可迁移的 harness 能力，而非针对单一模型的提示词技巧。
- 评估体系完整：7 维自动评分 + 系统盲测人类验证 + 成本-性能分析，还证明了自动基准与人类偏好的正相关（r=0.34）。

## 局限

- 任务面窄：目前只在"论文→海报"上完整验证，幻灯片/网页/视频等多媒介输出列为未来工作，跨任务普适性尚未证明。
- 演化启动成本高：7 天、224 个子智能体、123+ 次迭代才得到 DesignHarness，小团队复现门槛不低。
- 自主优化在 80.88 分平台停滞，靠人类引导才到 88.39——"完全自主的递归自改进"边界有限，人工介入仍是重要杠杆。

## 个人评价

这篇与之前覆盖的 HarnessX（06-16）、Harness-G（08-02）、OpenForgeRL（07-25）一脉相承：2026 年 agent 圈的共识是"模型权重之外，harness 才是系统性能的杠杆"。AutoDesign 的差异点在于把 harness 演化做成了闭环自优化：优化器本身也是智能体，用 rollout 反馈改 harness 代码，用接受门防过拟合——本质上是"训练系统而非训练模型"。它证明了即使模型参数完全冻结，仅靠系统性改进周边系统，也能让 DeepSeek V4 Pro 从 34.73 冲到 54.29、让弱模型追平强模型的大部分差距。

对我最有启发的是两条工程纪律：一是"一次只改一个组件+可归因判定"，这直接解决了 agent 系统迭代中最头疼的"改了但不知道哪个改动生效"问题；二是接受门把开发集变成防过拟合闸门，任何自改进型 agent 管线（技能演化、prompt 优化、harness 演化）都应该照抄这个设计。另外成本前沿数据很有说服力——用便宜模型+好 harness 在大多数场景下比贵模型+裸 harness 更划算，这对资源有限的团队是重要的选型参考。
