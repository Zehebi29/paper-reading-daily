# Skill Self-Play: Pushing the Frontier of LLM Capability with Co-Evolving Skills

**arXiv**: 2607.22529 | **GitHub**: https://github.com/Qwen-Applications/skill-self-play | **机构**: Qwen Large Model Application Team, Alibaba (多校联合)

---

## 一句话总结

Skill-SP 提出了一个基于技能协同演化的自对抗框架，通过 Proposer-Solver-Controller 三组件 RL 循环，在任务多样性和验证可靠性之间取得了平衡，在工具调用和逻辑推理上分别实现了最高 +42.9 和 +12.0 的绝对提升。

## 问题背景

当前大模型自我演化面临一个核心困境：环境绑定的自对抗方法能提供可靠验证但任务空间窄小，而开放式自生成能扩展任务多样性但缺乏可靠验证，误导性奖励会污染训练循环。作者认为，代理技能（agent skills）可以作为中间地带来调和这一矛盾：每个技能确保在特定场景下深度可验证的执行，同时动态路由跨技能保持任务开放性。

## 核心方法

- **技能库驱动的三组件协同演化架构**：Proposer 根据动态采样的技能生成挑战任务，Solver 探索解决方案，Controller 根据执行反馈更新和扩展技能库
- **双流任务生成策略**：技能引导生成流（结构化优先）+ 开放探索生成流（新模式发现），混合构建训练池
- **边界追踪课程机制**：使用前沿奖励（frontier reward）评估任务难度，自动定位 Solver 的学习边界
- **技能库动态演化**：Controller 自动精炼现有技能、修剪过时技能、从探索流引入新技能
- **GRPO 策略优化**：Proposer 和 Solver 均使用 Group Relative Policy Optimization 更新

## 亮点

- **理论创新**：将代理技能作为自对抗训练中的结构化媒介，成功解决了任务多样性与验证可靠性的核心矛盾
- **实验结果强劲**：在工具调用上对 Ministral-3-8B 实现 +42.9 绝对提升，将一个几乎无法工作的模型拯救为有效代理
- **模块化设计**：技能库的精炼/修剪/引入机制完整自扩展，不依赖外部强教师模型
- **代码开源**：GitHub 仓库已公开，基于 Qwen 生态，实验设置透明

## 局限

- 大型和超大型规模的逻辑推理任务（ZebraLogic XL）对于弱基础模型改善有限，纯自对抗需要最低能力阈值
- 仅在两类任务上验证（工具调用、逻辑推理），涉及更复杂任务（如 coding agents、web 浏览）的扩展性待研究
- 5 轮自对抗循环的训练成本及取决于多次 Solver 滚动的计算开销未披露

## 个人评价

这篇文章的核心贡献在于将“技能”从推理时的组件升级为训练时的结构化媒介，这是一个不错的角度。与之前读过的 SkillAxe、MetaSkill-Evolve 等工作不同，Skill-SP 不只是精炼已有技能，而是让 Proposer-Solver-Controller 三者通过 RL 循环共同演化，这个架构更完整。特别是双流设计（技能引导 + 开放探索）解决了单纯依赖技能库会导致过专业化的问题，这个细节很重要。

从工程角度看，这篇工作对实际产业落地有启示意义：对于弱基础模型，纯“放养”式 self-play 往往无效，而技能结构化引导可以带来惊人的翻身。这对 GWS 项目的可能启示是：如果给予 weld seam 识别代理一个“技能库”（如不同类型缝的检测规则、路径规划策略），并通过 RL 让它自己学习什么时候调用哪种技能，可能会效率更高。
