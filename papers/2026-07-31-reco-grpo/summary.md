# ReCo: Reweighting GRPO Against Distributional Concentration

**arXiv**: 2607.26862 | **GitHub**: 无 | **机构**: Seoul National University, Graduate School of Data Science

---

## 一句话总结

ReCo 提出了一种双层重权重方法，在 response 层面和 token 层面同时纠正 GRPO 的分布浓缩问题，在 5 个数学推理基准上将 Pass@64 平均提升 +3.1~+11.3 点，尝试解决已被广泛报告的“GRPO 降低基础模型推理能力”问题。

## 问题背景

1. 已有工作发现 GRPO 尽管提升了小 k 值下的采样效率，但 Pass@k (大 k 时) 反而低于基础模型，表明 GRPO 缩减了推理路径的覆盖范围。
2. 笔者发现 GRPO 的更新会浓缩到基础模型已经有高概率生成的正确解答上，而丢失了低概率但仍正确的解答。
3. 这个现象在 Agent RL 的上下文中尤其关键，因为 agent 需要多样化的推理路径来处理复杂多变的环境任务。

## 核心方法

1. 分析 GRPO 更新的两个机制: (a) response 层面——高概率回答通过重复出现占据群体梯度, (b) token 层面——重要性比率响应强化已经更大概率的 token。
2. 提出 response-level expected occurrence normalization: 用期望出现次数 (G * π_θold(o|q)) 的倒数作为权重，避免高概率回答凭借重复出现占据梯度。
3. 提出 token-level variance ratio: 用 pθ(1-pθ) / p_old(1-p_old) 替代标准的 pθ/p_old，使更新压力更大地放在还未饱和的决策点上 (多个候选 token 仍可行)。
4. 实际中用长度归化的概率 π╱θold 作为“期望出现次数”的代理，减少长度偏差。
5. 末尾裁剪与 KL 罚项保持与 GRPO 一致，只更改权重分配。

## 亮点

1. 诊断清晰: 确认了 GRPO Pass@k 降级的根本原因是分布浓缩，并用 KDE 可视化了这个效应。
2. 双层修正架构精巧: 从 response 和 token 两个层面同时解决问题，缺一不可。
3. 在 Llama-3.1-8B-Instruct 上效果惊人: GRPO 导致基础模型平均下降 13.5 点，ReCo 几乎完全恢复 (+11.3)。这说明 GRPO 的浓缩问题在弱基础模型上更严重。
4. 训练动态分析: ReCo 在提升奖励的同时保持了更高的多样性 (Distinct-2, Self-BLEU)，而 GRPO 快速提升奖励但丢失多样性。

## 局限

1. 仅在数学推理基准上验证，未在更广阔的 Agent 任务 (如 SWE-bench, WebShop, ALFWorld) 上测试。
2. 无公开 GitHub 代码，实验基于 verl 框架实现，复现成本较高。
3. 仅用于 RLVR (verifiable reward) 场景，不适用于需要学习奖励模型的 agentic RL 场景。
4. response-level 权重依赖于模型概率估计，这在大型模型中可能不稳定。

## 个人评价

ReCo 是一篇精巧的论文。它的核心贡献不是发明新的 RL 算法，而是深入分析已有算法 (GRPO) 的局限并给出精确的修正方案。这类“做减法”的工作在实际生产中往往比“做加法”更有价值。

对于 Agent RL 领域而言，GRPO 是当前最广泛使用的基础算法（如 DeepSeek-R1, Agent-R1, TMAX 等都基于 GRPO）。ReCo 解决的浓缩问题在 Agent RL 中可能更严重，因为 agent 任务的解空间更大、路径更长。笔者在 Llama-3.1-8B-Instruct 上的结果尤其有说服力: GRPO 可以让模型“变笨”（平均从 59.7 跌到 46.2），而 ReCo 能恢复这部分损失。这对于不能用巨大模型的团队特别有意义，因为 GRPO 的浓缩效应在小模型上更明显。

不过，未在真正的 Agent 任务上验证是一个明显缺陷。GRPO 的浓缩问题在 agentic RL 中可能因为更长的交互序列而更严重，但也可能因为 agent RL 的奖励更疏等因素而不同。很期待看到 ReCo 在 swe-bench 或 webshop 上的扩展实验。
