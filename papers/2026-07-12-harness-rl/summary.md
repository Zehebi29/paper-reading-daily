# Learning to Control LLM Agent Harnesses with Offline Reinforcement Learning

**arXiv**: 2607.05458 | **GitHub**: https://github.com/Hik289/Agentic-RL-harness.git | **机构**: University of Toronto + Emory University

---

## 一句话总结

本文首次将 LLM Agent 的执行线架（harness）视为可学习的控制层，通过离线强化学习训练一个轻量级控制器来决定何时观察、检索、调用工具、检查、修改和提交，实验表明该方法能一致性地改善验证行为并在部分场景显著提升最终任务质量。


## 问题背景

当前 LLM Agent 的改进通常聚焦于提示词、模型参数或手写工作流，但执行 harness 被视为固定基础设施。然而这个控制层实际上是策略的一部分：固定规则如“始终检查”在任务已完成时浪费预算，而“写完就提交”则可能在答案未验证时失败。问题核心在于：如何让执行 harness 本身能够学习优化自己的决策序列？

## 核心方法

1. **Harness MDP**: 将 harness 控制层正式化为有限地平 Harness MDP，状态包含当前轨迹、草稿状态、已收集证据、工具输出、验证器反馈、之前失败和剩余预算。动作空间包括 OBSERVE/RETRIEVE/CALL-TOOL/DRAFT/CHECK/REVISE/SUBMIT 七种结构化动作。
2. **离线强化学习训练**: LLM 执行器冻结不动，只训练轻量级控制器。从离线滚动缓冲区中采用优势加权回归 (AWR) 训练，仅使用终端任务评分奖励。
3. **Harness Maturity Score (HMS)**: 提出新的评价指标，独立于最终答案正确性，衡量 harness 是否遵循可靠的执行模式。
4. **离线缓冲受限观**: 关键发现 - 最终任务质量提升受限于离线缓冲中是否存在高回报轨迹支撑，但过程行为可以在更宽泛条件下改变。

## 关键结果

| 实验场景 | 主要结果 |
|:---|:---|
| 6个受控领域 + 2个公开基准 | 控制器一致性改善验证行为 |
| tau-bench 零售场景 | 最大的最终质量提升 |
| AgentBench DB-Bench | 选择性提升最终答案质量 |
| 结构化验证器编程场景 | 显著提升 |
| 行为克隆 (BC) 对比 | AWR 显著优于纯粹拷贝 |
| 强制检查 (Forced CHECK) 对比 | 增益不是简单多加检查解释的 |

## 亮点

1. **视角独特**: 首次将执行 harness 作为可学习控制层，而非固定基础设施。
2. **清晰框架**: Harness MDP + 离线 AWR + HMS 提供了完整理论和工程方法。
3. **开源代码**: GitHub 已公开，可复现。
4. **深刻局限性分析**: 明确指出离线缓冲支持的边界。

## 局限

1. 控制器仅从离线滚动中学习，无法发现缓冲区中不存在的新高回报行为模式。
2. 评估聚焦于有明确奖励规则的场景，更开放任务可能需进一步验证。
3. LLM 执行器冻结，无法联合优化，可能失去更大提升空间。

## 个人评价

这篇文章的视角很有意思。当所有人都在研究怎么训练更好的模型、设计更好的提示词时，这篇文章提醒我们：执行 harness 本身也是策略的一部分。这个观点和 HarnessX（我们 6月 16日覆盖的）有异曲同工之妙，但角度不同 - HarnessX 是可组合的 harness 工厂，而这篇文章关注的是用 RL 学习 harness 控制策略。

特别有意思的是 HMS 的设计思想：不仅关注答案对不对，还关注过程是否可靠。这对于工程化部署很重要 - 在生产环境中，我们希望 Agent 不只是偶尔答对，而是始终遵循可靠的工作流程。这个观点对 GWS 项目也有启发：搜索算法的执行 harness 也可能是可优化的。

不过文章的局限性也很明显：离线学习的上限受制于缓冲区质量，冻结 LLM 可能失去联合优化的潜力。如果能让控制器和 LLM 同步训练，可能会更强。
