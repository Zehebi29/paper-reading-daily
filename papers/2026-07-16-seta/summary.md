# SETA: Scaling Environments for Terminal Agents

**arXiv**: 2607.10891 | **GitHub**: https://github.com/camel-ai/seta | **机构**: CAMEL-AI (Oxford / KAUST / 多合作方)

---

## 一句话总结

SETA 提出了可扩展的终端环境生成框架，构建了目前最大的开源可验证终端 RL 数据集 SETA-Env (4,567 个环境)，用 GRPO 训练 Qwen3-8B 在 Terminal-Bench 2.0 上达到了 12% 的最佳记录。

## 问题背景

终端命令行是一个通用的交互式界面，涵盖从系统操作到数据科学的广泛任务，但由于缺乏天然的监督数据、可执行环境和可靠验证机制，扩展终端 agent 的 RL 训练面临显著挑战。现有数据集在可执行性、接地性、难度控制和 RL 验证方面往往只满足部分要求，缺乏全面的解决方案。

## 核心方法

1. **SETA-Synth 管道**: 将多种来源（GitHub 仓库、文档、现有数据集）转换为标准化的 RL 环境，包含任务指令、可执行环境和自动验证器。
2. **SETA-Evol 管道**: 从现有环境出发，通过自适应难度控制和多样性扩展生成新环境，实现规模化扩张。
3. **统一验证机制**: 两个管道共享相同的验证器设计，确保生成环境的可靠性。
4. **全开源发布**: 提供 4,567 个终端 RL 环境，规模超过所有现有开源数据集。

## 关键结果

| 实验 | 配置 | 结果 |
|:---|:---|:---|
| Terminal-Bench 2.0 pass@1 | Qwen3-8B + GRPO + SETA-Env | **12%** (8B 规模最佳) |
| Terminal-Bench 2.0 pass@1 | DeepSeek-V4-Flash (baseline) | 40% |
| Terminal-Bench 2.0 pass@1 | DeepSeek-V4-Flash + SETA-Env | 43% (+3pp) |
| Terminal-Bench 2.0 pass@5 | DeepSeek-V4-Flash (baseline) | 54% |
| Terminal-Bench 2.0 pass@5 | DeepSeek-V4-Flash + SETA-Env | 58% (+4pp) |
| 数据集规模 | SETA-Env | **4,567** 个环境 (最大开源) |

## 亮点

1. **全面性**: 同时满足接地性 (基于真实源)、可执行性 (实际可运行)、难度自适应、RL 验证 —— 突破了现有工作只做到部分的局限。
2. **可扩展性**: 两级管道设计使得环境规模可以持续扩张，SETA-Evol 的自适应难度控制能避免简单重复生成。
3. **开源完整性**: 代码、数据集、模型、训练管线全部开源 (Apache-2.0)，对研究社区着后经典战役意义重大。
4. **跨模型验证**: 在 Qwen3-8B 和 DeepSeek-V4-Flash 两个模型上均验证了有效性，说明数据集质量可靠。

## 局限

1. 终端任务的复杂度受限于环境生成器的能力，难以覆盖极端复杂的生产环境任务。
2. Qwen3-8B 的 12% 绝对性能仍然较低，说明终端 agent 的基本能力还有巨大提升空间。
3. 环境验证器的设计依赖于人工定义的验证规则，对于更开放的任务可能难以自动化。

## 个人评价

SETA 是一篇“基础设施类”的重要工作。它没有提出新的 RL 算法，而是在数据环境层面做了一个非常牢固的系统贡献。对于我们研究 GWS 和工业机器人 agent 的人来说，SETA 的两级环境生成架构和自适应难度控制思路很有借鉴意义。特别是 SETA-Synth/SETA-Evol 的分离设计，让我想到了我们在 GWS 中的点云处理管线——同样是“初始生成 + 迭代优化”的双阶段设计。

另外，在 DeepSeek-V4-Flash 上的提升 (pass@1 +3pp) 比 Qwen3-8B 上的赛道只能说明这个数据集对小模型更有价值，大模型可能已经在预训练中拥有了部分终端能力。这与我们在 GWS 中观察到的“小模型更需要精品数据”的规律一致。
