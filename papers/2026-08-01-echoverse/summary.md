# Echoverse：用于规模化训练计算机使用智能体的深度演化环境

**arXiv**: 2607.28074 | **GitHub**: https://github.com/microsoft/Echoverse | **机构**: Microsoft Research

---

## 一句话总结

微软研究院提出 Echoverse，一个“深度演化”的合成环境工厂：把规格编译成自带数据库的可运行应用、用数据库接地验证器给任务评分，并通过共同进化循环让环境与模型一起变强，9B 模型在 14 个评估集上平均从 36.5% 提升到 67.1%，距教师模型 GPT-5.4（80.7%）仅 14 分。

## 问题背景

计算机使用智能体从“行动改变状态”中学习，但最有价值的应用（邮件、银行、医疗）都是登录墙后的有状态系统，无法直接在真实系统上训练：不可重置、会被限流、没有真值。近年流水线能批量生成合成环境，瓶颈从“数量”转移到了“每个环境内部的质量”：行为深度够不够、是否针对智能体真正失败的交互、能否随模型一起改进。
## 核心方法

- 环境工厂（两阶段）：Phase 1 把少量种子规格编译成 FastAPI + React + SQLite 的应用，用可机器检查的 claims 验证并修复，直到≥95% claims 通过；Phase 2 在活数据库上重新落地（reground）任务语料，验证可解性，直到≥95% 语料通过验证
- 深度的操作化定义：环境要支持任务语料要求的每条工作流端到端完成，分解为行为保真、状态一致、工作流深度、权威验证、领域价值五个属性，在构建时对可检查的声明逐一验证
- 数据库接地评分（grounded grading）：任务参考在生成时直接对数据库执行 SQL 铸出，WRITE 任务用 sqldiff 检查状态变更，LLM 只做“结果 vs 参考”的窄比较，不看轨迹不看截图
- 共同进化循环：每次评分 rollout 读两遍——归因到环境的缺陷被修复（修复优先于训练），归因到模型的失败成为训练信号；修复纪律：绝不弱化目标来提高通过率
- 监督 + RL 两用：21,009 条 GPT-5.4 验证轨迹做 rejection-sampled 蒸馏；RL 用 group-relative policy gradient，轨迹级接地奖励（GPT-4.1 比较）+ 每步密集奖励（GPT-4.1 vision 二值），每个 turn 拆一行、全组中心化 advantage
- 能力世界（capability worlds）：把单个控件（日期选择器、嵌套筛选）在数十百种布局中批量渲染，训练“技能”而非“某个界面”
## 关键结果

主结果（14 个评估 split 平均任务成功率）：

| 模型 | 平均成功率 |
|:---|:---|
| Base（Qwen3.5-9B 对齐到浏览器动作空间） | 36.5% |
| Ours πSFT（21,009 条验证轨迹监督训练） | 67.1% |
| GPT-5.4（教师模型） | 80.7% |

其他关键数据：

- 深 vs 浅世界（两个实时 WebVoyager 域）：浅世界训练让 Allrecipes 从 80.0 跌到 75.0（低于不训练）、Hugging Face 持平 48.0；深世界两者都提升（80.0→85.0、48.0→65.0）
- 能力技能迁移：held-out 日期选择器 34.0 → 57.3，held-out 筛选面板 62.8 → 84.8；训练任一技能也提升另一个（日期训练→held-out 筛选 82.1；筛选训练→held-out 日期 50.7）；+Both 提升 Online-Mind2Web 29.5 → 34.3
- 共同进化：修复 EchoStay 的 guest-count 控件后，基于该世界训练的模型从 16.2% → 38.5%（两轮）；EchoForum 前端修复让 37 个任务从 0 解到 36；EchoChat 验证器重新对齐让可评分任务从 34% 到 99%
- RL 结果：5 个世界、32 张 GPU，held-out judged score 58.8% → 68.0%（约两个 epoch）
- 缩放实验：轨迹数从 6,400 增到 20,000 时 WebVoyager 持平（54.8→55.6）、Online-Mind2Web 反而下滑（40.1→37.2）；增加环境数量则两者持续上升
- 实时网络迁移：WebVoyager hosted 66.5 → 71.5、datacentre 50.9 → 55.6；Online-Mind2Web hosted 40.5 → 43.4、datacentre 29.5 → 37.2（均为 πSFT）
## 亮点

- 状态即数据库（而非像素）：奖励可接地、重置精确、评分难以游戏，这是环境能同时当 benchmark 和 RL 环境用的根基
- 把“环境质量”变成可操作、可验证的工程：深度被拆成机器可检查的 claims，而不是口号
- 共同进化循环诚实处理了合成环境的缺陷：失败先归因（环境/任务/验证器 vs 模型），修复优先于训练，且绝不弱化目标；一个共同根因的修复可以清除大批任务（如 guest-count 控件修复恢复 24 个任务中的 15 个）
- 完整开源：4 个环境 + 任务 + 数据库接地验证器（MIT 协议），配套博客与 HuggingFace 数据集，可复现性强
- 能力世界的思路很妙：把“某个控件学不会”这个具体诊断变成训练目标，且证明技能可以跨控件迁移

## 局限

- 评估任务只发布 4 个世界的子集（EchoStay、EchoForge + 两个能力世界），完整的 10 域 Echo 家族未开源，训练语料也不发布，无法完全复现 67.1%
- 密集每步奖励重新引入 LLM judge（GPT-4.1 vision），虽然论文用三个耦合保证接地奖励主导，但 judged signal 的成本与风险仍在
- 迁移到开放网络的增益有限（WebVoyager hosted 66.5→71.5），作者也承认训练域与公开 benchmark 覆盖重叠很小，真实世界的强化学习迁移仍是开放问题

## 个人评价

这篇论文最有价值的地方是把“环境工程”从 benchmark 建设提升为训练方法论的核心。对 GWS 这类机器人路径规划研究也有直接启发：仿真环境的“深度”（状态一致性、物理真实性、可验证的接地评分）比环境数量更重要，而“共同进化”——用模型失败来修复环境本身——正是 sim-to-real 研究中容易忽视的环节。论文反复强调 LLM judge 判轨迹是意见、判“结果 vs 数据库参考”才是事实，这与实验中用传感器/几何真值做验证的原则一致。

RL 部分的设计也很干净：轨迹级接地奖励 + 每步密集奖励的双项组合，以及“最终步密集奖励在轨迹判错时强制归零”的耦合，是防止 reward hacking 的实用工程细节。还有一个很值得借鉴的细节：任务池筛选用 pass@4 保留中间区带（解得出 1-3 次的任务），丢弃“始终解得对”和“始终解不出”的极端，因为两者的 advantage 都为零、不产生梯度——这个式子在自己的 RL 实验里可以直接用。
