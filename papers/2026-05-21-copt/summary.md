# CopT：连续空间中的对比On-Policy思考——通用与Agentic推理

**arXiv**: [2605.20075](https://arxiv.org/abs/2605.20075) | **GitHub**: [sdc17/CopT](https://github.com/sdc17/CopT) | 机构: Georgia Tech

---

## 一句话总结

CopT 把「先思考再回答」反过来——让模型先写草稿答案，再用连续嵌入空间的对比 KL 散度估计答案可靠性，仅当草稿不可靠时才触发思考，最终在数学、代码和 Agent 任务上准确率提升最高 23%、token 消耗降低最高 57%。

## 问题背景

标准 Chain-of-Thought（CoT）强制模型在回答前先思考，但这会引发「表演式推理」——即使模型内部已经知道答案，仍然生成大量冗余思考 token。这在 Agent 场景尤其严重：多轮交互的 token 成本线性膨胀，且延迟会影响用户体验。CopT 想解决的核心问题是：**能不能只在需要时才思考，而不是每次都从头推理？**

## 核心方法

- **反转推理流程**：先让模型直接输出 `</think>` 然后生成草稿答案，跳过显式思考步骤
- **对比可靠性估计**：利用草稿生成过程中缓存的连续 embedding（soft token），计算离散前缀 vs 连续前缀下的 token 概率差异，得到一个序列级 reverse-KL 估计量 κ_a。κ_a 越大，说明草稿在保留不确定性后不被模型自身支持 → 草稿可能不可靠
- **按需触发 On-Policy 思考**：仅当 κ_a 超过阈值时才进入思考模式，思考内容以草稿答案为条件生成，既可以利用草稿的部分正确信息，也可以纠正错误
- **动态草稿可见性控制**：思考过程中，第二个 KL 估计量 κ_r 逐块检测思考稳定性。如果当前思考块不稳定（高 κ_r），则隐藏草稿答案，防止不可靠信息误导后续推理
- **理论支撑**：在混合线性前缀假设下，κ_a 等价于隐推理状态 S 与答案 token A 之间的互信息 I(S;A)——只惩罚「答案相关的」不确定性，而非任意隐状态熵

## 关键结果

| 任务类别 | 数据集 | CopT vs CoT 效果 |
|:---|:---|:---|
| 数学 | GSM8K, Math500, AIME24, AIME25, GPQA Diamond | 准确率提升最高 23% |
| 代码 | HumanEval, LeetCode-Contest, MBPP | 显著优于 CoT |
| Agent | BFCL v4（工具调用）, ZebraArena（多轮交互） | 准确率提升，token 最高减少 57% |
| 多模型 | Qwen3-8B, Qwen3.5-2B, Qwen3.5-35B-A3B | 跨模型规模和架构一致有效 |

- 在相同准确率水平下，CopT 可将 token 消耗**减半**
- 方法完全 **training-free**，无需微调，即插即用

## 亮点

- **训练无关**：不需要 RL 微调或蒸馏，纯推理时方法，部署成本极低
- **可读推理**：不同于 latent CoT 方法（如 Coconut 用连续 thought token），CopT 保留完全可读的显式推理链
- **理论优雅**：连续 embedding 作为「免费」不确定性信号——不需要额外训练一个 verifier 模型
- **跨域泛化**：数学、代码、Agent 三类任务一致有效，说明方法不依赖特定领域结构

## 局限

- 依赖模型自带的推理能力：草稿答案本身需要有一定准确率，若基础模型在某个任务上表现极差（草稿几乎全错），CopT 的触发机制可能失效
- 阈值 τ_a 和 τ_r 需要按任务调参，论文没有给出自动选择阈值的方案
- 目前仅验证了 Qwen 系列模型，对 GPT/Claude 等闭源 API 模型（无法获取连续 embedding）的适用性未讨论

## 个人评价

这篇论文的核心洞察非常漂亮：**连续 embedding 是模型自带的免费不确定性信号**，不需要额外训练一个 critic 或 verifier。这比很多需要额外训练 reward model 的 RL 方法务实得多——尤其是在 Agent 场景中，训练成本是主要瓶颈。

CopT 在 Agent 任务上的应用特别值得关注：多轮工具调用天然需要按需思考——调用工具前确实需要推理参数，但某些简单查询可以直接走快速路径。这种「自适应推理深度」的思路，如果和 RL 训练结合（比如用 CopT 的 κ_a 作为训练信号），可能会产生更强的 Agent 训练方法。

不过，闭源 API 模型无法获取 embedding 这个局限是个实际问题。如果能用 logprobs 近似替代 embedding-based 的 KL 估计，也许能扩展到更多模型——这是值得跟进的方向。
