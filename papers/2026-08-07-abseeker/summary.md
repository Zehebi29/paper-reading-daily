# ABSeeker：通过答案回溯信用分配训练长程搜索智能体

**arXiv**: 2608.05102 | **GitHub**: https://github.com/PolarSeeker/ABSeeker | **机构**: 上海交通大学（MediaBrain 实验室，Siheng Chen 团队）

---

## 一句话总结

ABSeeker 提出 Answer-Backtracked Credit Assignment（ABC）框架，从标准答案回溯恢复中间证据线索，把稀疏的轨迹级奖励变成稠密的步骤级奖励，只用 8.5K 样本训练 Qwen3.5-4B，就在 BrowseComp 上达到 55.3%（带上下文管理），超过同规模 4B 智能体并匹敌约 30B 的搜索智能体。

## 问题背景

长程搜索智能体需要连续执行搜索、检索、验证、整合等多步操作才能到达最终答案，但现有训练方法在 SFT 和 RL 阶段把轨迹内所有步骤同等对待：成功轨迹的步骤全部视为正样本，失败轨迹的步骤全部视为负样本。实际上成功轨迹里可能包含错误或冗余步骤，失败轨迹里也可能有检索到关键证据的有用步骤——均匀对待无法给单个动作正确的信用分配，限制了长程搜索行为的针对性优化。

## 核心方法

- **Answer-Backtracked Clue Recovery（答案回溯线索恢复）**：给定问题和已验证答案，用 LLM 以 ReAct 循环主动搜索网页，从答案反向追踪恢复中间证据线索（实体、事实、关系），每条线索都用真实网页内容验证，形成连接问题与答案的证据链
- **Clue-Anchored Step Scoring（线索锚定步骤评分）**：每一步以 1.0 为基准分，发现/验证正确线索 +0.8、正确排除错误候选 +0.4、错误排除正确线索 −0.8、提交正确答案 +1.0、提交错误答案 −1.0，累积后裁剪到 [0, 2.0]，把二元结果监督转成稠密的步骤级奖励
- **ABC-SFT**：用 sigmoid 权重 w(rt) = 2σ(2(rt − 1)) 按步骤得分重加权每轮 loss，高得分步骤贡献更多梯度，低得分步骤信号弱化；保留成功和失败轨迹一起训练
- **ABC-GRPO**：步骤级得分直接作为 GRPO 奖励，组内归一化后用 γ=0.25 折扣计算步骤级 advantage，替换标准轨迹级 advantage；工具返回内容不参与优化
- **训练配置**：基于 Qwen3.5-4B，SFT 用 OpenSeeker 的 8.5K 轨迹（5.5K 正确 + 3.0K 错误）训 3 个 epoch；RL 用 1000 道题各 8 次 rollout，最多 200 步；线索恢复和步骤评分都用 DeepSeek-V4-Flash 作为 backbone

## 亮点

- **思路巧妙且可操作**：利用搜索任务"有标准答案即可回溯"的特性，用答案反向恢复证据线索作为固定的评分锚点，比基于模型自身置信度（IGPO）或仅验证关键步骤（CSO）的方法提供更稠密、更稳定的步骤监督
- **失败轨迹也有价值**：奖励分布分析显示失败轨迹中近 10% 的步骤得分高于 1.0（发现了有用线索），成功轨迹中约 4% 的步骤低于 1.0——ABC 能在这两类轨迹中分别挖掘正信号、压制负信号
- **数据效率惊人**：只用 8.5K 轨迹 + 1000 道题的 RL，4B 模型就在 xbench-2505 和 GAIA-text 上超过所有 30B 搜索智能体
- **全链路开源**：代码（46 stars）、模型权重（PolarSeeker/ABSeeker-4B-RL）都公开，复现门槛低

## 局限

- **依赖可验证的标准答案**：线索恢复必须从 ground-truth answer 出发，只适用于 BrowseComp 这类有唯一可验证答案的 benchmark，真实开放场景很难直接套用
- **评分规则和恢复质量都靠 LLM**：+0.8/+0.4/−0.8 的 delta 是人工设计的启发式，线索恢复和步骤评分都用 DeepSeek-V4-Flash 完成，其质量波动会传导到整个训练信号
- **只验证了 4B 规模**：作者自述受算力限制只做了紧凑模型实验，更大 backbone 上的增益是否保持未验证；且不带上下文管理时 BrowseComp 37.3 仍低于 QUEST-4B 的 40.0，优势部分依赖上下文管理技巧

## 个人评价

这篇是 SJTU MediaBrain 团队在 OpenSeeker（开源搜索智能体训练数据）之后的续作，思路很对我胃口：信用分配不靠模型自我估计，而是靠"答案可回溯"这个任务结构本身——先确定终点，再反推中间必须经过的证据点，然后给每一步对号入座打分。相比 G2PO（图结构信用分配）和 TRACE（回合级奖励分配），ABC 的锚点更客观、监督更稠密，而且把 SFT 和 RL 两个阶段都改造成了步骤级，消融显示每步改造都有稳定增益。

对 GWS 焊缝路径规划有个直接启发：规划任务的"最终答案"（有效焊缝路径）同样可以回溯成中间线索——关键焊点、约束条件、工艺参数边界。如果以后做长程规划智能体（比如多焊缝排序或多层多道规划），完全可以把"从目标焊缝质量回溯关键工艺节点"当成评分锚点，给每一步路径决策分配稠密 credit，而不是等整条路径走完再给一个稀疏的成功/失败信号。不过要注意 ABC 的代价：每步都要 LLM 打分，训练成本不低，且线索质量决定上限，工程上要先验证线索恢复的可靠性再投入。
