
# CompactionRL: Reinforcement Learning with Context Compaction for Long-Horizon Agents


**arXiv**: 2607.05378 | **GitHub**: 基于 THUDM/slime (github.com/THUDM/slime) | **机构**: Tsinghua University (Jie Tang Group)


---


## 一句话总结


CompactionRL 提出在长程任务 RL 训练中引入上下文压缩机制，让代理在超过上下文窗口限制后仍能继续执行和学习，在 SWE-bench Verified 上达到 66.8% Pass@1（+7.0点），并已实际部署到 GLM-5.2 的 RL 训练流程中。

## 问题背景

长程任务中，LLM 代理的交互轨迹很容易超出模型的上下文窗口限制，导致任务无法完成。上下文压缩（context compaction）是一种自然的解决方案——通过摘要历史交互状态来缩短上下文，但当前工作都是在 inference 环境下使用，将压缩引入到 RL 训练中仍是未探索的方向。

## 核心方法

1. **上下文压缩轮带技术：**在代理的长轨迹中插入压缩节点，用模型自己生成的摘要替代原始交互历史，从而在固定上下文窗口内继续扩展轨迹。

2. **Token-level 损失正则化：**解决压缩前后序列长度不均衡的问题，用 token 级别的概率平均替代序列级别的损失，避免长序列占据过大的更新权重。

3. **跨轨迹广义优势估计（Cross-Trajectory GAE）：**传统 GAE 只能在单条轨迹内传播信号，但压缩后的多段轨迹应当被视为一个完整轨迹。本文将被压缩分割的多段 GAE 连接起来，实现质效跨压缩边界的信号传播。

4. **摘要生成联合优化：**将任务完成和摘要生成作为联合目标优化，让模型学会如何有效压缩上下文。

## 关键结果

| 模型 | 方法 | SWE-bench Verified | Terminal-Bench 2.0 |
|:---|:---|:---:|:---:|
| GLM-4.5-Air (106B-A30B) | 基础模型 | 59.8% | 21.4% |
| GLM-4.5-Air (106B-A30B) | CompactionRL | **66.8%** (+7.0) | **24.5%** (+3.1) |
| GLM-4.7-Flash (30B-A3B) | 基础模型 | 50.5% | 13.4% |
| GLM-4.7-Flash (30B-A3B) | CompactionRL | **56.0%** (+5.5) | **20.2%** (+6.8) |

## 亮点

1. **实用性极强：**解决了真实环境中代理常见的上下文超限问题，并已在 GLM-5.2 (750B-A40B) RL pipeline 中实际部署。

2. **设计精巧：**Cross-Trajectory GAE 解决了压缩分步传播的信号问题，这是前人未触及的技术细节。

3. **开放源成熟：**基于已开源的 THUDM/slime 框架，代码可复现性高。

4. **结果强劲：**即使是 30B-A3B 的小模型，在 Terminal-Bench 2.0 上也提升了 6.8 点，说明方法对各规模均有效。

## 局限

1. CompactionRL 的增益在关闭压缩的 single-window 评估下不能一致性转移，存在 train-test mismatch。

2. 跨轨迹 GAE 仍是对完整轨迹信用分配的近似，早期摘要的长期影响可能未被完全捕捉。

3. 实验主要聚焦在代码工程类基准，扩展到更广的代理场景（如 web 交互、多模态）仍是未来方向。

## 个人评价

这篇的想法很直接但很实用——上下文压缩在现有 agent 框架中已经广泛使用（比如 codex/Claude Code/Codex CLI 都有 compact Handoff），但把它引入 RL 训练的确是一个被忽略的窗口。Token-level 损失正则化和跨轨迹 GAE 的设计很简洁但有效，这种“看似简单但解决了真实痛点”的工作我很喜欢。

最让人信服的是 GLM-5.2 已经在用这套方法，说明它不只是学术成果，而是真正经受了大规模 RL 训练的检验。如果要在自己的项目中实现类似机制，主要妣裕在于压缩节点的策略和摘要质量的平衡，这个可能需要一些属于工程优化的调参。
