# Do Agent Optimizers Compound? A Continual-Learning Evaluation on Terminal-Bench 2.0

**arXiv**: 2607.14004 | **GitHub**: https://github.com/relai-ai/Continual-Learning-Terminal-Bench | **机构**: RELAI / University of Maryland

---

## 一句话总结

这篇论文提出了一个根本性问题——Agent优化方法的增益是否能“复利”（compounding），并通过 Terminal-Bench 2.0 上的两阶段连续学习评估发现，只有内置回归控制（regression control）的 RELAI-VCL 方法能同时实现正向迁移和持续提升，而 GEPA 和 Meta Harness 均在复利场景下失败。

## 问题背景

当前大多数 agent 优化方法的报告只测试一次性效果——在固定 benchmark 上优化并报告提升。但生产环境中的 agent 是被递归应用的：新失败模式、新任务类型不断出现，已优化过的 agent 会被再次优化。一次性指标无法告诉我们：优化器在连续学习场景下是否能维持已有增益并持续进步。

## 核心方法

1. **两阶段连续学习评估框架**：第一阶段在初始任务集 Τ_1 上优化，然后测试向 Τ_1 ∪ Τ_2 的迁移能力，第二阶段在全集上再次优化。这分离了静态优化强度、未见任务迁移、续优能力三个属性。
2. **对比三种优化器**：GEPA（提示词优化）、Meta Harness（架构代码优化）、RELAI-VCL（可验证连续学习），使用相同的滚动预算。
3. **回归控制（Regression Control）**：RELAI-VCL 在优化循环中嵌入了回归控制机制，确保新优化不会破坏已解决任务的能力，这是其他两种方法缺失的。
4. **基线 agent**：所有方法从共享的未优化基线 agent 出发，保证公平对比。

## 关键结果

| 方法 | 静态阶段 1 | 迁移测试 | 阶段 2 (全集) | 全生命周期平均通过率 |
|:---|:---:|:---:|:---:|:---:|
| 基线 (未优化) | 58.7% | — | — | 58.7% |
| GEPA | 70.1% | 低于基线 (负迁移) | 66.0% | 66.0% |
| Meta Harness | 68.3% | 正向迁移 | 无提升 | 64.6% |
| RELAI-VCL | 71.2% | 正向迁移 | 持续提升 | **76.4%** |

*注：表格数据基于论文摘要和全文描述，具体数字可能有微调。*

## 亮点

1. **问题本质而精准**：“优化复利”这个问题是 agentic RL / agent 优化领域被忽略的核心问题，论文定义非常清晰。
2. **实验设计精巧**：两阶段评估分离了静态提升、迁移、续优三种能力，让“复利”可测量。
3. **反思性结论**：“回归控制是复利的前提”这个观察对整个领域都有指导意义——没有 regression control 的优化只是过拟合。
4. **开源工艺**：GitHub 仓库释放了基线、阶段 1 和阶段 2 的完整工艺，可复现性强。

## 局限

1. **仅测试了三种优化器**：砰场较小，无法表示所有 agent 优化方法的行为。
2. **仅使用 Terminal-Bench 2.0**：结论是否推广到其他场景（SWE-bench、WebShop、ALFWorld）仍待验证。
3. **没有开放源 RELAI-VCL 本身**：RELAI-VCL 是 RELAI 的专有引擎，只释放了优化后的 artifacts 而非源码。

## 个人评价

这篇论文对当前的 agentic RL 研究获益非常大。我觉得它的核心发现——“回归控制是优化复利的必要条件”——可以直接应用于我们正在做的工作。很多 agentic RL 方法（GRPO、DPPO 等）在单次优化中表现很好，但在连续学习场景下是否也能维持增益是一个很好的研究方向。对于我们在 GWS 中训练模型的场景，如果我们要做多轮优化（新数据源持续加入），必须考虑回归控制。另外，这篇文章的实验设计也值得借鉴——不要只看单次提升，而要看“如果再给一次优化机会，它还能继续提升吗？”这个问题。
