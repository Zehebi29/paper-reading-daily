# OpenAgent: Can Agents Generalize to the Open World? 揭示静态训练在工具使用中的脆弱性

**arXiv**: [2607.01084](https://arxiv.org/abs/2607.01084) | **GitHub**: [LAMDA-NeSy/OpenAgent](https://github.com/LAMDA-NeSy/OpenAgent) (代码将发布) | **机构**: 南京大学 LAMDA-NeSy | **ICML 2026**

---

## 一句话总结

论文正式定义了 Agent 开放世界化问题场景 OpenAgent，发现 SFT 和 RL 两种训练范式在环境分布迁移下均产生性能衰退（SFT 最高降 -67.7%），但失效机制不同：SFT 是“符号锚定”（表面模式匹配），RL 是“目的偏差”（强行完成）。提出的 PAFT（扰动增强细调）可显著改善 SFT 的开放世界化表现，最高提升 +28.6% 准确率 Delta。

## 问题背景

当前 LLM Agent 的训练（SFT/RL）均在静态环境下达到近乎完美的工具调用能力，但部署到真实世界时，API 迁移、工具图谱变化、用户指令模糊等导致性能悬崖式下降。现有基准的“闭集”性质遮蔽了这个问题，因此必须系统性地研究开放世界下的化表现。

## 核心方法

1. **OpenAgent 问题形式化**：定义四维度分布迁移——用户查询 (ΔQ)、工具集 (ΔA)、交互动态 (ΔO)、任务领域 (ΔD)
2. **四层诊断框架**：感知 (Perception)、交互 (Interaction)、推理 (Reasoning)、内化 (Internalization)，每层设计多种精细扰动
3. **PAFT (Perturbation-Augmented Fine-Tuning)**：在轨迹级别引入控制性扰动，包括环境反馈扰动 (EFP)、符号扰动和无解状态掺入，扩展训练分布的支撑集

## 关键结果

| 模型 | Tier-1 (感知) Acc Δ | Tier-2 (交互) Acc Δ | Tier-3 (推理) Acc Δ | Tier-4 RR |
|:---|:---:|:---:|:---:|:---:|
| Base (Qwen2.5-7B) | -29.8 | -8.5 | -8.5 | 12.2 |
| SFT-200 | -67.7 | -48.2 | -39.9 | 0.3 |
| SFT-200 + PAFT | **+28.6** | **+26.5** | **+22.7** | **99.3** |
| SFT-400 | -53.9 | -45.4 | -32.5 | 0.0 |
| SFT-400 + PAFT | +5.6 | +4.9 | -2.8 | 97.8 |
| SFT-800 | -50.4 | -45.3 | -28.0 | 0.2 |
| SFT-800 + PAFT | -4.1 | -5.3 | -9.8 | 99.6 |

**主要发现**：
- **SFT 的失效**：符号锚定 (symbolic anchoring)，表面模式匹配，训练步数越多反而越脆弱（过拟合）
- **RL 的失效**：目的偏差 (teleological bias)，能感知错误但仍强行完成，缺乏拒绝能力
- **共同失败**：逻辑反转 (Logic Inversion) 时两者均受损严重，表明都过拟合了动作的时序依赖关系

## 亮点

1. **问题形式化：** OpenAgent 的四维度迁移定义为后续研究提供了统一框架，可以成为 Agent 开放世界化的基础基准
2. **SFT vs RL 的系统性对比：** 往常只看最终指标，这篇文章深入剖析了两者的失效模式差异（开环 vs 闭环）
3. **轨迹级别数据增强：** PAFT 的设计精巧，不是简单输入增强，而是在轨迹中插入扰动并监督纠正续转，近似对策缩放的一种替代方案
4. **ICML 2026**，论文质量有保证

## 局限

1. 实验场景为合成沙箱，与真实世界复杂度还有差距（作者承认这是故意设计的控制实验）
2. PAFT 在训练初期改善显著（+28.6），但在训练后期效果很有限（-4.1），说明方法无法完全解决过拟合问题
3. 缺乏对 RL 的类似增强方法（PAFT 只作用于 SFT），RL 的目的偏差问题未解决
4. GitHub repo 尚未公开，代码可复现性待验证

## 个人评价

这篇文章给了一个很必要的“当头棒喝”：当前的 Agent 基准都是闭集的，SFT/RL 在闭集下达到近乎完美的表现，但只要环境略微变化，性能就悬崖式下降。这对我们普遍的“训练完就发布”思维是一个很好的警示。

特别有意思的是 SFT 和 RL 的失效差异：一个是“看不见”（开环），一个是“看见了但强行完成”（目的偏差）。后者对安全性更危险，因为 RL Agent 明知道工具不可用，却仍穿造结果。这是因为奖励设计默认每个问题都可解，缺乏“拒绝”的正确激励。这对我们设计 RL 奖励函数时是一个很好的启发。
